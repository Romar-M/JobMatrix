# JobMatrix — План разработки (Roadmap)

_От каркаса до production: адаптеры ~6 сайтов, матрица, оповещения о откликах со звуком, поиск резюме, деплой._

## Приоритетный минимум (MVP)

**Этап 0 → 1 → 2 (hh.ru + SuperJob) → 3 → 4 → 5 → 6 (Windows).**

Оповещения — это ядро продукта работодателя, поэтому этап 5 идёт **до** поиска резюме.

## Этап 0 — Каркас проекта
- [ ] Структура папок (`adapters/`, `notifications/`, `api/`, `storage/`, `launcher/`)
- [ ] `requirements.txt`: fastapi, uvicorn, sqlalchemy, apscheduler, httpx, beautifulsoup4, pytest
- [ ] `config/settings.py` — чтение `.env`, режим local/server
- [ ] `config/.env.example` — шаблон (APP_MODE, DATABASE_URL, ENABLED_SITES, SOUND_ENABLED)
- [ ] `storage/db.py` + `storage/models.py` — подключение и модели
- [ ] Минимальный `api/main.py` — FastAPI + `/api/ping` + WebSocket-эхо

## Этап 1 — База и модель данных
- [ ] Модели: `Company`, `Vacancy`, `VacancyListing`, `Response`, `Event`, `ResumeMatch`
- [ ] Схема БД (SQLite), миграции
- [ ] CRUD-эндпоинты для вакансий
- [ ] Тесты на модели и CRUD

## Этап 2 — Адаптеры сайтов (каркас на ~6)
- [ ] `adapters/base.py` — интерфейс `SiteAdapter` + модели данных
- [ ] `adapters/registry.py` — реестр, включение через `ENABLED_SITES`
- [ ] **hh.ru**: `fetch_vacancies` (без токена читает вакансии компании)
- [ ] **SuperJob**: `fetch_vacancies` (API-ключ)
- [ ] Заглушки `avito`, `rabota_ru`, `zarplata_ru` + 1 резервный слот (возвращают пусто, каркас готов)
- [ ] Тесты адаптеров (мок-ответы)

## Этап 3 — Веб-интерфейс (матрица)
- [ ] Таблица «вакансии × сайты»: строки — вакансии, столбцы — сайты
- [ ] Загрузка через `GET /api/vacancies`
- [ ] Кликабельные ячейки-ссылки на вакансии на сайтах
- [ ] Кнопка «Обновить сейчас»
- [ ] Автообновление по таймеру (fetch)

## Этап 4 — Сбор просмотров и откликов
- [ ] APScheduler: периодический сбор по всем сайтам
- [ ] `fetch_stats` — обновление `views_count` / `responses_count`
- [ ] Логирование сборов (`CollectLog`)
- [ ] Интервал через `.env`

## Этап 5 — 🔔 Оповещения о новых откликах (ядро!)
- [ ] `notifications/detector.py` — сравнение счётчиков, создание `Response` + `Event`
- [ ] `notifications/hub.py` — WebSocket-хаб, рассылка событий
- [ ] Эндпоинт `WS /ws/events`
- [ ] Браузер: WebSocket-клиент
- [ ] **Всплывающее окно** через Notification API (`requestPermission`)
- [ ] **Звуковой сигнал** через Web Audio API (вкл/выкл в настройках)
- [ ] Список событий `/api/notifications` + отметка прочитанных
- [ ] Fallback: SSE / long-polling, если WebSocket недоступен
- [ ] Тесты детектора (мок: счётчик вырос → событие)

## Этап 6 — Кроссплатформенный запуск
- [ ] `launcher/run.py` — единый запуск (сервер + планировщик + хаб + браузер)
- [ ] `start.bat` (Windows, pythonw, без окна)
- [ ] `start.sh` (Linux/macOS, nohup)
- [ ] Опционально: `tray.py` (иконка в трее)
