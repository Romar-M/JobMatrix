# JobMatrix — README

_Агрегатор вакансий работодателя: матрица «вакансия × сайт», отклики с оповещением и звуком, поиск резюме, плагинная архитектура на ~6 API._

# JobMatrix — панель работодателя по вакансиям и откликам

> Один экран: **строки — вакансии, столбцы — сайты размещения.**
> Новый отклик → всплывающее окно + звуковой сигнал.

## 📋 Описание

**JobMatrix** — веб-приложение **от лица работодателя**. У компании есть пул вакансий, которые она размещает на разных сайтах (hh.ru, SuperJob, Авито, rabota.ru и др.). JobMatrix собирает все размещения в одну таблицу-матрицу:

- **Строки** — вакансии компании.
- **Столбцы** — сайты размещения (hh.ru, SuperJob, Авито …).
- В ячейках — статус размещения: опубликовано/не опубликовано, дата, **просмотры**, **отклики** (если сайт даёт такие данные).
- Ячейки **кликабельны** — ведут на конкретную вакансию на сайте.
- **Новый отклик** → в браузере всплывает **оповещение + звуковой сигнал** (в реальном времени).
- Кнопка **«Найти человека»** по каждой вакансии: берёт фильтры вакансии, подбирает запрос и ищет подходящие **резюме** на сайтах — результат в отдельном столбце.

Проект работает **и локально, и на удалённом сервере**, запускается **в фоне одной кнопкой**, интерфейс — в браузере.

## 🚀 Функционал

- ✅ **Пул вакансий** — компания ведёт свои вакансии в одном месте
- ✅ **Матрица «вакансия × сайт»** — все размещения на одном экране
- ✅ **Сбор данных с сайтов** — официальные API + парсинг, где API нет
- ✅ **Просмотры и отклики** — статистика по каждой вакансии на каждом сайте
- ✅ **🔔 Оповещения о новых откликах** — всплывающее окно + звук, в реальном времени
- ✅ **«Найти человека»** — поиск резюме по фильтрам вакансии
- ✅ **Плагинные адаптеры на ~6 сайтов** — подключение нового сайта = один класс
- ✅ **Автообновление** — периодический сбор по расписанию
- ✅ **Веб-интерфейс** — из любого браузера, локально и на сервере
- ✅ **Кроссплатформенный запуск** — одна кнопка, фоновая работа (Windows / Linux / macOS)

## 🔌 Плагинная архитектура сайтов (каркас на ~6 API)

Все сайты — это **адаптеры**, реализующие единый интерфейс. Подключить новый сайт = написать один класс и зарегистрировать его.

| Ключ | Сайт | Способ получения данных |
|---|---|---|
| `hh_ru` | hh.ru | Официальное API (отклики, просмотры, резюме) |
| `superjob` | SuperJob | Официальное API |
| `avito` | Авито | API/парсинг (зависит от доступов) |
| `rabota_ru` | Rabota.ru | API/парсинг |
| `zarplata_ru` | Zarplata.ru | API/парсинг |
| `reserve` | Резерв под будущий сайт | — |

**Интерфейс адаптера** (единый для всех):

```python
class SiteAdapter(ABC):
    site_key: str          # "hh_ru"
    site_name: str         # "hh.ru"

    @abstractmethod
    async def fetch_vacancies(self) -> list[VacancyData]: ...
        # размещённые вакансии компании

    @abstractmethod
    async def fetch_stats(self, listing) -> Stats:
        # просмотры, отклики по размещению

    @abstractmethod
    async def fetch_responses(self, listing) -> list[ResponseData]:
        # новые отклики кандидатов

    def supports_resume_search(self) -> bool: ...
    async def search_resumes(self, query) -> list[ResumeData]: ...
```

Новые сайты добавляются в `adapters/` и регистрируются в `adapters/registry.py` — остальная система не меняется.

## ⚙️ Режимы работы

### Локально (одна машина)

- База — **SQLite** (файл `data/jobmatrix.db`).
- Интерфейс — `http://localhost:8000`.
- **Windows:** двойной клик по `launcher/start.vbs` — сервер в фоне, окна нет, браузер открывается сам. `launcher/start.bat` — то же, но окно мелькнёт на секунду.
- **Остановка (Windows):** двойной клик по `launcher/stop.vbs` (или `launcher/stop.bat`).
- **macOS:** двойной клик по `launcher/JobMatrix.app` — сервер в фоне **вообще без терминала**, браузер открывается сам (`JobMatrix.command` — альтернатива с кратковременным окном).
- **Остановка (macOS):** двойной клик по `launcher/stop.command`.
- **Linux:** `./launcher/start.sh` — фон; остановка — `pkill -f 'launcher/run.py'`.

### Удалённый сервер

- База — **PostgreSQL** (контейнер).
- Поднимается `docker compose up -d`.
- Доступ из любого браузера по адресу сервера.
- Код тот же — режим переключается конфигом (`.env`).

```bash
# Windows — одна кнопка, без окна консоли:
#   двойной клик по launcher\start.vbs
# Остановка:
#   двойной клик по launcher\stop.vbs

# macOS — одна кнопка:
#   двойной клик по launcher/JobMatrix.app (без терминала)
# Остановка:
#   двойной клик по launcher/JobMatrixStop.app

# Linux/macOS — универсально из терминала:

# В браузере:
http://localhost:8000
```

## 🔧 Запуск без окна: как это устроено

### Windows

1. `start.vbs` вызывает `_start_hidden.bat` со скрытым окном (`WScript.Shell.Run ..., 0`).
2. `_start_hidden.bat` находит `pythonw` (или `pyw`, или `python`) и запускает `launcher/run.py` в фоне.
3. `run.py` работает даже без консоли: `stdout/stderr` уходят в `data/logs/app.log`, PID пишется в `data/jobmatrix.pid`, браузер открывается сам через пару секунд.
4. Если порт уже занят (сервер уже запущен) — `run.py` не падает, а просто открывает браузер.
5. Остановка: `stop.vbs` → `_stop_hidden.bat` → убивает процесс по PID-файлу (запасной вариант — по порту 8000).

### macOS

1. `JobMatrix.command` запускается двойным кликом в Finder (открывает терминал).
2. Скрипт проверяет, не запущен ли уже сервер (`pgrep`), при необходимости поднимает его через `nohup python3 launcher/run.py` в фоне.
3. Браузер открывается сам (командой `open` + через сам `run.py`).
4. Окно терминала закрывается сразу — сервер живёт в фоне.
5. **Первый запуск:** если Finder спрашивает разрешение или ничего не происходит, один раз выполните в терминале:
   ```bash
   chmod +x "Путь/к/JobMatrix/launcher/JobMatrix.command" "Путь/к/JobMatrix/launcher/stop.command"
   ```
   (или в папке `launcher`: `chmod +x JobMatrix.command stop.command`).
6. Остановка: двойной клик по `stop.command` → убивает процесс по PID-файлу (запасной вариант — `pkill`).

## 🐛 Если что-то не работает

- Смотрите лог: `data/logs/app.log` — там все ошибки.
- Сервер запущен, но браузер не открылся → просто откройте `http://localhost:8000`.
- `start.bat` мелькает и закрывается → это нормально: сервер уже стартовал в фоне, проверьте по адресу выше.
- Порт занят другим приложением → поменяйте `PORT` в `config/.env`.

## 🍏 macOS: приложения `.app` (вообще без терминала)

Для macOS добавлены **настоящие приложения** — никаких окон и терминала вообще (в отличие от `.command`, который на секунду показывает Terminal).

| Приложение | Действие |
|---|---|
| **`JobMatrix.app`** | Двойной клик → сервер поднимается в фоне, браузер открывается сам |
| **`JobMatrixStop.app`** | Двойной клик → сервер останавливается (бесшумно) |

Оба лежат в `launcher/`.

### Первый запуск (один раз)

1. Скопируйте папку `JobMatrix` на Mac.
2. Откройте Терминал и выполните один раз:
   ```bash
   cd "путь/к/JobMatrix/launcher"
   chmod +x JobMatrix.app/Contents/MacOS/JobMatrix \
           JobMatrixStop.app/Contents/MacOS/JobMatrixStop \
           install-mac.sh
   ```
   Или проще — запустите `install-mac.sh`: он сам выставит права и предложит скопировать приложения в `/Applications`:
   ```bash
   ./install-mac.sh
   ```
3. Первый запуск из Finder может спросить подтверждение (приложение не подписано): **правый клик** по `JobMatrix.app` → **«Открыть»** → **«Открыть»**.

### Как это устроено

- `JobMatrix.app` — стандартный macOS-бандл: `Contents/Info.plist` + исполняемый скрипт `Contents/MacOS/JobMatrix`.
- Скрипт: находит папку проекта → проверяет, не запущен ли уже сервер (curl `/api/ping`) → при необходимости поднимает его через `nohup python3 launcher/run.py` в фоне → открывает браузер.
- **Терминал не показывается**: исполняемый файл бандла запускается Finder'ом напрямую, консоль не открывается.
- Ошибки пишутся в `data/logs/app.log`.
- Если `.app` лежит в `/Applications`, скрипт ищет проект в `~/JobMatrix`, `~/Documents/JobMatrix` или `~/Documents/Obsidian Vault/Programs/JobMatrix`.

### Остановка

Двойной клик по **`JobMatrixStop.app`** → процесс убивается по PID-файлу (запасной вариант — по порту 8000). Приложение пришлёт системное уведомление «JobMatrix остановлен».
